## 实施原则

1. 群疗判定与 AOE 读条时序分为两个独立阶段实现和验证，禁止混在一次改动中排障。
2. 先增加能在修改前失败的测试，再修改生产代码。
3. 所有模块规则仍按技能优先级逐条检查；规则未满足、目标不存在、技能不可用或按键缺失时必须继续检查后续规则。
4. 不使用固定技能发送限流代替游戏状态；所有玩家动作以施法事件确认，首次投递未被接受时只在真实 GCD 队列窗口补发一次，不使用任意敌方读条近似匹配对应 AOE。
5. DiGua 声明预警和事件类型，受管理的兼容桥补充真实读条 Spell ID。普通 AOE 以 `UNIT_SPELLCAST_START` 的真实敌方读条为主；吸奶盾共用真实读条入口，优先按实际 `cast.endsAt + 2` 秒进入阶段 3，并允许精确复刻 DiGua 姓名板倒计时在 `11.7 + 2` 秒后回退进入。两条输入均由现役美德文档约束，不能推广倒计时方案到普通 AOE。
6. AOE 语义继续只占用 `AOE事件类型` 和 `AOE事件阶段`；桥接握手、玩家动作确认和 GCD 剩余使用通用状态字段，不按怪物或机制增加色块。
7. 每个阶段完成后保存相关 diff、测试结果和未验证风险。最终打包后不自动重启应用，由用户手动重启。
8. 无美德黎明之光使用严格真实血量计数：至少 3 个有效成员 `<95%` 才有资格；95% 不计入，治疗吸收不参与该计数。该行为已进入 1.2.1.22 模块并完成本地回放。

## 已确认的技术约束

### DiGua 数据边界

当前 DiGua 在 `CustomEncounterBar` 调用 `C_EncounterTimeline.AddScriptEvent` 时可能将 `spellID` 固定为 `0`，且许可禁止分发修改版。仓库因此在 Fuyutsui 内提供兼容桥接，不修改 DiGua 文件；它按关键时间轴 API 能力为标准预警重发带真实读条 Spell ID 的时间轴事件。

因此采用以下交付策略：

- `Fuyutsui/core/diguabridge.lua` 是当前兼容映射的唯一机器可读注册表；`FuyutsuiDiGuaBridge/Bridge.lua` 只转发初始化调用，不维护第二份机制清单。
- `spellID=0` 或无法完成可信读条匹配时，只保持资源预留；受保护读条仅可按 0.5 秒窄时间相关性匹配，实际血量形成群疗条件后仍可由反应式群疗兜底。
- 桥接实现随 Fuyutsui 进入运行资源、应用包和 AddOns 同步；DiGua 主动取消会传播到桥接事件。DiGua 更新后按关键 API/数据能力继续工作，版本字符串只用于诊断；能力缺失时才安全停用。
- 目标 WoW 客户端的时间轴状态枚举与引导事件顺序仍需实战验证；此前 `allowUnverifiedChannels=false`，引导机制只预留资源。

### 群疗保持状态

`至少 3 人治疗负荷达到 10% 且总负荷达到 45%` 只能触发爆发开始，不能逐帧充当完整技能链条件。首个治疗落地后缺口可能立即低于阈值，如果没有保持状态，下一帧会错误跳过黎明之光、鸣钟或后续治疗。

模块系统需要提供一个通用、配置化的短期布尔状态：

- 触发条件由模块配置，不在运行时硬编码奶骑名称或阈值。
- 触发后保持 5 至 6 秒。
- 保持状态不占插件色块。
- 关闭逻辑、切换模块、状态失效或运行时停止时必须清空。
- 保持状态只允许继续已有爆发技能链，不能绕过目标存在、真实治疗需求、技能冷却和美德持续条件。


### AOE 阶段编码

现有两个协议字段保持不变：

```text
AOE事件类型
0 = 无
1 = 普通 AOE
2 = 治疗吸收

AOE事件阶段
0 = 无
1 = 资源预留
2 = 普通 AOE 美德执行窗口
3 = 吸奶盾可信提交：预铺美德并等待真实治疗吸收
4 = 普通 AOE 已生效
5 = 停止启动非紧急普通 GCD
```

阶段 5 只禁止会占用美德窗口的普通 GCD。运行时进入类型 2/阶段 5 时作废既有普通 GCD 待发送动作，并独立于模块规则顺序拦截新的普通 GCD；圣疗术、非 GCD、驱散和受伤友方 NPC 治疗可执行。

实现内容：

2. 增加“全队治疗负荷总和”指标。

### 阶段三：奶骑模块规则

允许修改：

- `Core/BundledModuleInstaller.cs` 与 Mac UI/打包入口；缺失模块正常补装，同一内置模块 ID 按包内语义版本更高自动备份并原位升级，跨 ID 的历史模块仍需精确匹配已知缺陷版本 SHA-256，其他同版本或更高版本模块保留

- 本文档与 PRD 中的实施记录

完整规则事实来源必须覆盖：圣疗连续帧保护、玩家自身自律排除、队友非法圣疗的失败退让、玩家优先与真实血量目标、美德爆发链、治疗吸收、神性之手、复仇之怒、灌注闪现、神圣震击、清洁术、92% 裸读边界、脱战治疗、友方 NPC、正义盾击、黎明之光和输出填充。不得再用测试场景数量代替技能清单。

现有按键、宏、目标槽位和技能名称保持不变；模块只组合这些既有契约。圣疗仍由运行时统一执行同目标双帧确认。带普通冷却的技能以冷却转正确认释放；带充能层数的技能也允许以层数下降确认释放。技能确认只提供结果和失败退让，不阻塞连续按键或下一轮规则选择。

模块核心顺序：

```text
圣疗和紧急保命
> 对应读条的美德执行窗口
> 反应式群疗美德
> 美德光环内真实多人群伤时优先黎明之光
> 圣能足够时永恒之火
> 美德持续期内圣洁鸣钟
> 其他群疗收尾
> 全员真实血量至少 70% 时清洁术
> 低于 90% 或存在治疗吸收的单抬急救
> 无美德三人轻群伤黎明之光
> 其余 90% 至 95% 轻伤单抬
> 低压力资源与输出填充
```

清洁术使用 `H70` 作为唯一边界字段：`H70 > 0` 时先执行单抬急救，`H70 == 0` 时清洁术高于普通单抬、治疗吸收、施法保护、友方 NPC 和输出填充。可信 AOE 美德窗口及已经启动的群疗爆发链仍高于清洁术。

无美德黎明之光使用新增模块计数 `H95`（`UnitsBelowHealth`，阈值 95）。目标条件为：`H95 >= 3`、无美德、无治疗吸收、战斗中、AOE 阶段为 0 或 4，并且圣能至少 3 或存在神圣意志。该规则位于低于 90%/治疗吸收急救之后、90% 至 95% 轻伤单抬和输出填充之前。全员满血、只有 1 至 2 人低于 95%、3 人恰为 95%、阶段 1/3/5 均不命中。三人轻群伤成立时，神圣意志用于免费黎明之光；不成立时才按既有低压力条件由正义盾击消费。


### 阶段三补充：连续动作投递

允许修改：

- `Runtime/ShigureRuntime.cs` 与 `Runtime/RuntimeDependencies.cs`
- `Modules/ModuleStore.cs`，仅移除不再使用的 GCD 分类输出
- `Tests/Shigure.Core.ContractTests/Program.cs`
- 本文档、PRD、macOS 架构文档与 CHANGELOG

运行时每个有效扫描周期重新求值最高优先级动作。动作首次投递后等待 `UNIT_SPELLCAST_START/SUCCEEDED` 对应的动作序号与技能编号；普通 GCD 动作无论首次投递还是优先级抢占，都只能在 `公共冷却剩余 <= 50ms` 时发送。同技能同目标的规则升级只合并实时优先级，不重复发键；目标变化可在队列窗口替换。圣疗和明确的非 GCD 技能可立即抢占，读条期间普通动作保持静默。冷却、充能、圣能和免费施法增益变化保留为兼容确认，确认失败仍按同技能同目标退让处理。

普通群疗触发：

```text
明显治疗缺口人数 >= 3 且全队治疗负荷总和 >= 45
或
真实血量 < 70% 的人数 >= 2 且全队治疗负荷总和 >= 50
或
真实血量 <= 50% 的人数 >= 2
```

美德后顺序：

```text
真实多人群伤且圣能 >= 3 或神圣意志存在：美德 > 黎明之光 > 圣洁鸣钟 > 后续治疗
非多人群伤且圣能 >= 3 或神圣意志存在：美德 > 永恒之火 > 圣洁鸣钟
圣能 < 3 且无神圣意志：美德 > 圣洁鸣钟 > 永恒之火
```


### 阶段四：真实读条状态机

允许修改：

- `Fuyutsui/core/aoewarning.lua`
- `Fuyutsui/core/events.lua`
- `Fuyutsui/Fuyutsui.toc`，加载统一状态机入口
- `Tests/Shigure.Core.ContractTests/Program.cs`

状态机要求：

1. DiGua 普通 AOE 与吸奶盾预警都只创建阶段 1。
2. 收到敌方读条事件后，验证时间轴非零 `spellID`，不从本地身份表猜测。
3. 匹配成功后读取真实开始时间、结束时间、总时长与剩余时间。
4. 仅当 `剩余时间 > 1秒 + 实际GCD + 扫描输入余量` 时允许启动非紧急普通 GCD。
5. 进入最后安全窗口后输出阶段 5。
6. 剩余时间首次不超过 1 秒后输出阶段 2，并保持到美德确认释放、读条结束或读条取消。
7. 总时长不超过 1 秒时，匹配成功后立即进入阶段 2。
8. 读条在阶段 2 前取消或打断，不得输出阶段 2。
9. 同一读条只允许开启一次美德执行窗口。
10. 无法读取安全数值、遇到受保护值或没有身份匹配时安全降级为阶段 1。
11. 吸奶盾不使用阶段 2；真实读条按实际 `cast.endsAt + 2 秒`进入阶段 3，结束时点不可用时按精确匹配的 DiGua 姓名板倒计时 `11.7 + 2 秒`回退。两种入口都必须经过现役状态机的阶段 5、取消、延迟和生命周期校验。模块按 `类型 2 + 阶段 3` 预铺美德，再等待真实治疗吸收启动后续群疗。

## 游戏内分级验收

### 第一级：逻辑关闭观察

1. 打包并同步插件，但不自动重启 App。
2. 用户手动重启 App；插件同步后按提示执行 `/reload`，内置桥接随既有 Fuyutsui 重新加载。
3. 保持治疗逻辑关闭，观察 DiGua 预警和 AOE 阶段日志。
4. 验证预警只进入阶段 1，无关读条不进入阶段 2。
5. 验证匹配读条依次进入阶段 5和阶段 2。
6. 验证吸奶盾优先以真实 `cast.endsAt` 为锚点，结束后完整等待 2 秒进入阶段 3；结束时点不可用时才以 DiGua 姓名板 11.7 秒倒计时为锚点。两条路径均须经过阶段 5，阶段 5 后不得投递普通 GCD；明确中断、失败或条件取消均保持阶段 1。

任何阶段错误都在此停止，不开启自动治疗。

### 第二级：受控开启逻辑

1. 在低风险环境验证普通 AOE 阶段 2 和吸奶盾 `类型 2 + 阶段 3` 都会连续投递美德，冷却确认后立即停止重复投递。
2. 验证读条打断不会消耗美德。
3. 验证 1 至 2 人普通明显缺口继续单抬。
4. 验证至少 3 人低于 85% 且真实总生命缺口至少 50 才触发真实群伤；重伤边界为低于 70%，圣洁鸣钟还要求至少 3 人治疗缺口达到 15% 且总缺口大于 50。
5. 验证美德内真实多人群伤且资源足够时实际顺序为美德、黎明之光、鸣钟与后续治疗。
6. 验证无美德时 3 人 94% 使用黎明之光，而全员满血、仅 1 至 2 人低于 95%、3 人恰为 95% 均不使用。
7. 回归清洁术、圣疗、玩家自疗、脱战治疗、神圣意志正义盾击和审判填充。
