## 目标

模块最终需要实现以下目标：

1. 紧急治疗优先保证生存，不因输出循环抢占灵界打击资源。
2. 在单体、双目标和群怪之间使用可解释的资源循环。
3. 将死亡使者的核心技能窗口与血债、沸点、赤色天灾和死神印记等状态关联。
4. 防御技能按照伤害类型、目标数量、血量和技能时间轴判断，而不是只按单一血量阈值判断。
5. 对自动化无法可靠判断的技能保留手动控制，避免误放关键技能。
6. 所有新增状态都有明确生产者、消费者、测试和回滚边界。

### 已实现技能优先级

模块不是把所有技能按固定技能表平铺，而是按战斗上下文分层判断：先处理生存和高压，再处理凋零减伤/爆发准备，最后进入高亮和输出循环。同一层内仍按规则从上到下执行。

```text
【生存与高压层】
灵界打击：生命值 <= 35%，且符文能量 >= 40
灵界打击：生命值 <= 50%，且符文能量 >= 80
灵界打击：生命值 <= 60%，且符文能量 >= 40
治疗石 / 银月城生命药水：生命值 <= 20%，治疗石优先
吸血鬼之血：生命值 <= 25%；团本首领战不自动使用
冰封之韧：生命值 <= 20%，且至少 3 个当前仇恨目标；团本首领战不自动使用

【凋零减伤与爆发准备层】
枯萎凋零：战斗未满 15 秒时站定至少 1 秒后释放；达到 15 秒后 Buff 消失即释放，不受移动状态限制
亡者复生 -> 巫妖之躯 -> 符文刃舞：爆发开关开启时按独立技能槽顺序释放，位于冰封之韧之后
死神印记：有效近战目标、生命值不低于 20% 时优先使用
符文刃舞：至少 1 个有效敌人且爆发开关开启，不再要求三目标或等待死神印记

【高亮与输出循环层】
高亮血液沸腾：`auras.沸点 > 0`
高亮心脏打击：`auras.午夜舞步 > 0`
高亮精髓分裂：`auras.破灭 > 0`
精髓分裂：10 层血债且骨盾未满时优先；骨盾剩余 5 秒或层数不足时提前补充
无高亮循环：2-3 次心脏打击后，在符文能量 >= 60 时血液沸腾
灵界打击：符文能量达到 80 时泄能，避免心脏打击继续顶满资源
死神的抚摩：移动时对 5-30 码有效敌对目标补骨盾和建立仇恨
心灵冰冻：目标或焦点可打断读条进入最后 0.5 秒时使用，无 GCD
死亡脚步：手动
反魔法护罩：手动
暂停
```

### 阶段二：资源与状态闭环（本地已实现，待实战复核）

**目标：**确认模块使用的所有层数、充能和资源字段与游戏内实际状态一致。

**模块侧工作：**

- 复核符文、符文能量、血债、沸点、白骨之盾和赤色天灾的条件语义。
- 区分“当前可用资源”和“下一轮即将恢复的资源”。
- 避免在灵界打击即将需要时消耗符文或符文能量。
- 调整骨髓分裂、血液沸腾、心脏打击之间的资源优先级。
- 为同一技能增加目标、距离、战斗状态和技能可用性边界。

**插件侧工作：**

- 如果当前光环协议只能提供存在性，增加层数和剩余时间的可靠输出。

**验收：**

- 单体木桩连续 60 秒，不能出现资源字段明显跳变。

## 修改边界

### 只改模块 JSON

适用于：

- 技能优先级顺序。
- 血量、资源和敌人数阈值。
- 已有字段的组合条件。
- 已注册技能的自动或手动开关。
- 已有目标选择器的使用方式。

修改入口：`BundledModules/blood-deathbringer-12.1.json`。

### 必须改 Fuyutsui 插件

适用于：

- 新增光环、减益、技能或充能数据。
- 新增层数、剩余时间或施法状态。
- 新增敌方读条、引导和可打断状态。
- 新增伤害类型或战斗事件。
- 新增目标类型、Boss 标记或可靠敌人数。

主要入口：

- `Fuyutsui/class/DeathKnight.lua`
- `Fuyutsui/core/` 下对应状态或事件文件
- 生成后的 `config/DeathKnight.json`
- 生成后的 `keymap/deathknight.json`

### 必须改 Shigure 运行时

适用于：

- 多目标比较和自动目标路由。
- 技能发送确认、重复抑制和失败退让。
- 预测资源溢出或技能窗口。
- 跨多个插件状态的战斗状态机。
- 需要独立于模块规则顺序执行的安全拦截。

主要入口：

- `Runtime/`
- `Modules/`
- `Presentation/`
- 对应的 `Tests/Shigure.Core.ContractTests/Program.cs`

## 单一事实来源和同步顺序

技能和状态变更按以下顺序处理：

```text
设计文档
  -> Fuyutsui 权威源或模块 JSON
  -> 生成 config/keymap
  -> 契约测试
  -> 应用构建和模块打包
  -> WoW 内 /reload
  -> 木桩或副本实测
```

禁止只修改生成后的 `config/DeathKnight.json` 或 `keymap/deathknight.json` 作为长期修复。生成物必须能从 Fuyutsui 源文件重新得到；如果生成流程不能覆盖某个字段，应补充生成器或记录明确同步点。
