## 治疗预测与实际覆盖协议

奶骑专精 1 的团队协议步长为 11：原有生命值、职责、驱散和三个光环字段保留在偏移 1-6，偏移 7-9 分别为每个成员的 `预期需求`、`爆发需求`、`持续需求`，偏移 10 为实际 `美德道标` 光环，偏移 11 为 `可治疗`。距离不可用、单位死亡或单位不可协助时，`可治疗` 为假；运行时和规则选择器都拒绝把这类单位作为治疗目标。运行时使用当前生命缺口、近期掉血速度和已确认 AOE 阶段生成预测值；预测值用于资源预留和规则调度，不把时间轴预警当作实际伤害。

## 2026-09-09 根因修复

- 满血且有可消耗圣能时，规则顺序先释放正义盾击，避免被健康群疗或输出填充吞掉。
- 战斗中团队满血时，灌注优先转为圣能；脱战只在接近到期时转化，避免脱战阶段反复读条。
- 审判由当前目标优先宏处理：当前目标满足敌对、存活和距离条件时直接使用，否则回退坦克目标；规则移除会阻断回退宏的目标几何前置。
- 所有团队治疗目标统一经过 `可治疗` 和距离门禁，吸收盾目标在脱战与战斗阶段分别使用对应治疗/资源条件。
- 正义盾击的动作确认不再使用跨技能的通用圣能变化兜底：只能由自身动作码或专用匿名盾击回退确认；同时以 Fuyutsui 生成的 selector-target keymap 为唯一键位来源，当前目标宏绑定为 `ALT-NUMPAD8`。

状态协议同时输出 `单目标需求`、`多人爆发需求`、`多人持续需求`、`预计治疗人数`、`美德主目标`、`美德覆盖人数`、`美德转移需求` 和 `美德覆盖溢出`。其中 `多人爆发需求` 与 `预计治疗人数` 是吸收盾和近期生命缺口共同形成的短期压力预测，可作为反应式美德的明确入口；这避免等待吸收被刷空后才看到真实血量缺口。美德成功施放时记录施法目标；随后从团队成员的实际美德光环读取覆盖集合，窗口内目标选择器 `HighestHealingDeficitWithAura` 只消费已经确认覆盖且当前实际治疗缺口最高的目标。

美德有两类入口：普通实际/预测多人治疗压力，以及 DiGua 提供的 AOE/吸奶盾预警。普通入口消费 `真实群伤`、`多人爆发高压` 和达到阈值的 `多人爆发预测`；`多人持续高压` 继续用于美德窗口内的资源调度，不单独替代爆发入口。DiGua 入口消费 `AOE事件类型` 与 `AOE事件阶段`。预测字段不能单独伪造 AOE 时间轴事件，但吸收盾达到多人爆发阈值时可以直接打开反应式美德。

Shigure 步骤日志会记录这些预测和覆盖字段，实战复盘应同时关注预测压力、实际覆盖人数、主目标和转移需求；最终美德释放仍必须以 WoW 动作确认事件为准。

## 为什么采用当前方案

DiGua 的 `NamePlateEnterCombat.lua` 并不是等 WoW 战斗日志落盘后再判断，而是在游戏内监听姓名板，目标进入战斗且符合仪式首领条件时直接调用：

```lua
CustomEncounterBar(132334, 11.7, "准备吸奶盾", unit)
```

曾经尝试在 `FuyutsuiDiGuaBridge` 中钩住 `addonTable.CustomEncounterBar`。这个方案无效：Lua 文件开头 `local _, addonTable = ...` 得到的是兼容桥插件自己的 addon table，不是 DiGua 的 addon table，因此永远收不到 DiGua 的调用。插件日志又只在退出游戏时刷新，不能作为实时施法信号。

现役实现优先消费可读取的真实施法事件；只有真实结束时点受保护或缺失时，才直接复刻 DiGua 产生该条倒计时的姓名板条件，并把同一条实时信号送入 Fuyutsui。它不修改或分发 DiGua 文件，也不依赖插件日志落盘；DiGua 版本字符串只用于诊断，兼容判断以所需 API 和数据能力为准。

## 现役触发条件

`FuyutsuiDiGuaBridge/Bridge.lua` 监听：

- `NAME_PLATE_UNIT_ADDED`
- `NAME_PLATE_UNIT_REMOVED`
- `PLAYER_ENTERING_WORLD`
- `PLAYER_REGEN_DISABLED`

姓名板单位必须同时满足以下条件才建立吸奶盾倒计时：

1. 单位键为 `nameplate*`，且可被玩家攻击。
2. 副本 ID 为 `2993`。
3. 地图 ID 为 `2588` 或 `2590`。
4. 玩家位于室外。
5. 单位等级等于玩家等级加 1。
6. 单位能量类型为 1。
7. 单位分类为 `elite`。
8. 单位已经进入战斗。
9. 单位没有生物家族。

姓名板出现时条件可能尚未全部成立，所以桥接每秒复查，直到命中或单位消失。同一姓名板只触发一次；姓名板移除时停止轮询并取消尚未完成的对应倒计时。

## 状态机与释放时点

两条输入进入同一个 AOE 状态机。

真实施法路径：

```text
匹配吸奶盾真实施法
-> AOE事件类型 2 + AOE事件阶段 1（资源预留）
-> cast.endsAt 后开始 2 秒等待
-> 临近 virtueReadyAt 进入 AOE事件类型 2 + AOE事件阶段 5（美德前最后 GCD 保护）
-> cast.endsAt + 2 秒
-> AOE事件类型 2 + AOE事件阶段 3（美德执行窗口）
-> 奶骑模块对单位 1 施放美德道标
-> WoW 玩家动作事件确认成功后停止重投
```

DiGua 姓名板回退路径：

```text
DiGua 姓名板条件命中
-> ObserveAOEDiGuaBar(132334, 11.7, "准备吸奶盾", unit)
-> AOE事件类型 2 + AOE事件阶段 1（资源预留）
-> 11.7 秒倒计时结束
-> 若已绑定真实读条，以真实结束时刻开始 2 秒等待
-> 若没有可绑定的真实读条，以 DiGua 倒计时结束时刻开始 2 秒回退等待
-> 临近 virtueReadyAt 进入 AOE事件类型 2 + AOE事件阶段 5（美德前最后 GCD 保护）
-> AOE事件类型 2 + AOE事件阶段 3（美德执行窗口）
-> 奶骑模块对单位 1 施放美德道标
-> WoW 玩家动作事件确认成功后停止重投
```

“读条后 2 秒”的首选基准是匹配施法记录的 `cast.endsAt`；受保护字段无法读取且存在成功终态时，使用成功终态回调时刻。没有可绑定真实读条时，DiGua 的 11.7 秒姓名板倒计时作为受保护回退。真实读条一旦绑定，DiGua 后续更新不能覆盖其时间。两种路径都必须经过完整 2 秒才开放美德。全员健康不阻止预铺美德，因为此处依据是机制时点，不是当前血量缺口。

类型 2/阶段 5 位于 `virtueReadyAt` 前最后一个 GCD 的预留区间，不是普通 AOE 的读条前窗口。App 运行时进入该阶段时必须清除已排队的普通 GCD，并独立于模块规则顺序拦截新普通 GCD；圣疗术、非 GCD、驱散和受伤友方 NPC 治疗可以通过。该保护避免阶段切换前已经排队的圣光术、神圣震击等技能把美德推迟一个 GCD。

`Fuyutsui/core/aoewarning.lua` 中只有图标 `132334` 或名称 `准备吸奶盾` 可进入这条 `diguabar` 路径。事件完成后阶段 3 保持到美德得到确认，以及治疗吸收生命周期或本地窗口结束；不得在首次零吸收采样时立即退回阶段 1。

无 DiGua 预警时，只有至少 3 个有效单位各自达到至少 10% 最大生命值的吸收量、合计吸收比例至少达到 45%，并连续两帧满足条件时，才允许建立反应式吸收事件；最大生命值不可读时保持 fail-closed，不触发该事件。

## 与真实读条路径的关系

兼容桥仍监听 `UNIT_SPELLCAST_START/STOP/INTERRUPTED/FAILED/SUCCEEDED`，用于客户端能提供可用施法事件时的真实读条路径。当前实战证明，吸奶盾不能只依赖这条路径：受保护字段或缺失终态会使事件长期停留在阶段 1。

因此吸奶盾允许两条输入进入同一个 AOE 状态机：

- 可用的真实施法事件按实际 `cast.endsAt + 2 秒` 提交吸奶盾事件。
- 真实结束时点不可用时，成功终态回调时刻作为实际回退；如果连可匹配终态也不可用，DiGua 的实时姓名板 `CustomEncounterBar` 等价信号按 `11.7 + 2` 秒提交受保护回退。
- DiGua 回退事件按姓名板 `unitKey` 分离并分配独立内部事件 ID；只有同一单位的重复回调按影响时点去重，姓名板移除只取消该单位的事件，不能按全局图标或时间合并多个怪物。

两者的目标都是生成 `类型 2 + 阶段 3`。奶骑模块不自行判断怪物身份、读条或倒计时，只消费这两个协议字段。

## 不可破坏约束

- 不得再次通过兼容桥自己的 `addonTable.CustomEncounterBar` 尝试钩住 DiGua。
- 不得依赖退出游戏后才更新的插件日志驱动实时状态。
- 不得仅凭单个吸收数值、全员血量或战斗时间构造阶段 3；无 DiGua 的反应式吸收事件必须满足当前代码中的多单位比例阈值和连续两帧门槛。
- 不得在真实读条或 11.7 秒回退倒计时结束当帧直接进入阶段 3；必须再等待 2 秒。
- 不得删除或仅依赖模块规则实现类型 2/阶段 5 的最后 GCD 保护；进入阶段时必须作废既有普通 GCD 待发送动作。
- 美德链路修改不得顺带调整其他技能优先级；若正义盾击、牺牲祝福或消耗品等奶骑独立优先级发生变更，必须在优先级文档、模块 JSON 和契约测试中同步记录。
- 不得修改或打包分发第三方 DiGua 源码。
- 不得改变模块对 `AOE事件类型 == 2 && AOE事件阶段 == 3` 的消费契约，除非协议生产者、消费者、回放和迁移同时更新。
- 普通 AOE 继续要求匹配真实敌方读条；不得复用吸奶盾的裸姓名板倒计时提交方式。
- 预测时间、实际结束时间和美德可用时间必须保持独立：已绑定真实读条时，预测只允许影响资源预留；成功终态必须重新计算 `impactAt`、`virtueReadyAt` 并将锚点标记为 `actual`。没有可绑定真实读条时，才允许使用明确标记的 DiGua 回退。
- 任何新数据源接入前必须先定义其证据等级和覆盖优先级。必须在 Lua 回放中覆盖“预测时间与成功时间不同”“受保护结束时间缺失”和“没有终态时使用 DiGua 回退”三种场景。

## 日志验收标准

最新实现的一次正确吸奶盾链路在运行日志和必要的 AOE 调试诊断中必须能看到：

1. `AOE预警：治疗吸收 / 资源预留`。
2. 影响时点前进入类型 2/阶段 5；此后不得再出现普通 GCD 的实际投递，运行时拦截日志可以作为辅助证据。
3. 真实施法路径在 `cast.endsAt + 2 秒`、受保护终态路径在终态回调时刻 + 2 秒、无可匹配终态时在 DiGua 倒计时结束 + 2 秒出现 `AOE预警：治疗吸收 / 等待生效`；真实读条成功后必须切换为 `impactAnchor=actual`，纯回退路径保持 `impactAnchor=diguabar`。普通 Shigure 日志不声称传输未进入协议的 `cast.endsAt`。
4. 随后第一个符合条件的 GCD 为 `施放 美德道标`。
5. 最终出现 `技能确认：美德道标 已释放`；只有“已投递到 WoW 进程”不算成功。

2026-09-03 用户提供的早期实战日志已有两次“姓名板倒计时到美德确认”的闭环：

- `01:49:46` 进入资源预留，`01:50:01` 进入等待生效并投递美德，`01:50:03` 确认释放。
- `01:51:28` 进入资源预留，`01:51:46` 进入等待生效并在同秒确认美德释放。

这些记录证明了姓名板回退和动作确认能够工作，但发生在“真实 `cast.endsAt` 锚点”和运行时阶段 5 统一拦截修复之前，不能替代最新包的最终实战验收。阶段时间会受扫描采样和姓名板首次满足条件的时刻影响，验收重点是所选时点锚点正确、完整 2 秒后置延迟、阶段 5 后无普通 GCD 抢占，以及最终动作确认，而不是日志秒数必须完全相同。

## 修改与验证清单

修改上述三处事实来源或相关同步/打包逻辑前，必须逐项确认：

1. 本文描述与生产代码仍一致。
2. `Tests/Shigure.Core.ContractTests/Fixtures/aoe-warning-replay.lua` 覆盖真实结束时点、受保护终态回退、预测覆盖保护，以及无终态时的 DiGua 回退 `1 -> 5 -> 3`。
3. `Tests/Shigure.Core.ContractTests/Program.cs` 仍锁定姓名板事件、`132334`、`11.7`、取消入口、错误钩子禁令，以及阶段 5 的运行时统一 GCD 保护和待发送动作作废。
4. 运行 `luajit Tests/Shigure.Core.ContractTests/Fixtures/aoe-warning-replay.lua Fuyutsui/core/aoewarning.lua`。
5. 运行完整契约测试；若仓库已有无关失败，必须单独报告，不能把 Lua 回放通过等同于全套通过。
6. 新包实战至少验证一次“资源预留 -> 最后 GCD 保护 -> 结束后 2 秒进入等待生效 -> 美德已释放”，并保留真实读条结束时点、阶段切换、阶段 5 后动作和最终确认的时间戳日志。

若未来确认 DiGua 改变了副本、地图、单位筛选、图标或 11.7 秒参数，必须同时更新桥接、本文和契约测试；不能只改单个常量。
