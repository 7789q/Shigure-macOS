## 治疗预测与实际覆盖协议

奶骑专精 1 的团队协议步长为 11：原有生命值、职责、驱散和三个光环字段保留在偏移 1-6，偏移 7-9 分别为每个成员的 `预期需求`、`爆发需求`、`持续需求`，偏移 10 为实际 `美德道标` 光环，偏移 11 为 `可治疗`。距离不可用、单位死亡或单位不可协助时，`可治疗` 为假；运行时和规则选择器都拒绝把这类单位作为治疗目标。奶骑生命字段不计入尚未落地的读条治疗预估，`UNIT_HEALTH` 即时刷新；团本以四帧覆盖作为轮询兜底。插件发布近期掉血预测，运行时以解码后的真实生命缺口校正其下限并加入治疗吸收；预测值用于资源预留和规则调度，不把时间轴预警当作实际伤害。

状态协议同时输出 `单目标需求`、`多人爆发需求`、`多人持续需求`、`预计治疗人数`、`美德主目标`、`美德覆盖人数`、`美德转移需求` 和 `美德覆盖溢出`。其中 `多人爆发需求` 与 `预计治疗人数` 是吸收盾和近期生命缺口共同形成的短期压力预测，可作为反应式美德的明确入口；这避免等待吸收被刷空后才看到真实血量缺口。美德成功施放时记录施法目标；随后由运行时从与目标选择器相同的团队成员美德光环像素读取覆盖集合，窗口内目标选择器 `HighestHealingDeficitWithAura` 只消费已经确认覆盖且当前实际治疗缺口最高的目标。

美德有可信机制预铺与实际多人压力两类入口。机制入口消费 `AOE事件类型` 与 `AOE事件阶段`；反应式入口由各场景的模块规则决定，不使用旧的压力保持状态授予新开美德资格。团本使用独立的血线与鸣钟资源分支，不能套用大秘境阈值。预测字段不伪造 AOE 事件。

Shigure 步骤日志会记录这些预测和覆盖字段，实战复盘应同时关注预测压力、实际覆盖人数、主目标和转移需求；最终美德释放仍必须以 WoW 动作确认事件为准。

## 为什么采用当前方案

DiGua 的 `NamePlateEnterCombat.lua` 并不是等 WoW 战斗日志落盘后再判断，而是在游戏内监听姓名板，目标进入战斗且符合仪式首领条件时直接调用：

```lua
CustomEncounterBar(132334, 11.7, "准备吸奶盾", unit)
```

曾经尝试在 `FuyutsuiDiGuaBridge` 中钩住 `addonTable.CustomEncounterBar`。这个方案无效：Lua 文件开头 `local _, addonTable = ...` 得到的是兼容桥插件自己的 addon table，不是 DiGua 的 addon table，因此永远收不到 DiGua 的调用。插件日志又只在退出游戏时刷新，不能作为实时施法信号。

现役实现只允许技能身份明确的吸奶盾施法建立结束锚点；姓名板倒计时只用于资源预留。结束时点受保护时仍可使用可读 DurationObject 或对应成功终态，但受保护的技能身份不能仅凭单位条件或时间接近得到确认。它不修改或分发 DiGua 文件，也不依赖插件日志落盘；DiGua 版本字符串只用于诊断，兼容判断以所需 API 和数据能力为准。

## 现役触发条件

`FuyutsuiDiGuaBridge/Bridge.lua` 监听：

- `NAME_PLATE_UNIT_ADDED`
- `NAME_PLATE_UNIT_REMOVED`
- `PLAYER_ENTERING_WORLD`
- `PLAYER_REGEN_DISABLED`

姓名板单位必须同时满足以下条件才建立吸奶盾倒计时：

1. 单位键为 `nameplate*`，且可被玩家攻击。
2. 副本 ID 为 `2993`。
3. 地图 ID 为 `2588` 或 `2590`。
4. 玩家位于室外。
5. 单位等级等于玩家等级加 1。
6. 单位能量类型为 1。
7. 单位分类为 `elite`。
8. 单位已经进入战斗。
9. 单位没有生物家族。

姓名板出现时条件可能尚未全部成立，所以桥接每秒复查，直到命中或单位消失。同一姓名板只触发一次；姓名板移除时停止轮询并取消尚未完成的对应倒计时。

## 状态机与释放时点

两条输入进入同一个 AOE 状态机。

真实施法路径：

```text
匹配吸奶盾真实施法
-> AOE事件类型 2 + AOE事件阶段 1（资源预留）
-> cast.endsAt 后开始 2 秒等待
-> 临近 virtueReadyAt 进入 AOE事件类型 2 + AOE事件阶段 5（美德前最后 GCD 保护）
-> cast.endsAt + 2 秒
-> AOE事件类型 2 + AOE事件阶段 3（美德执行窗口）
-> 奶骑模块对单位 1 施放美德道标
-> WoW 玩家动作事件确认成功后停止重投
```

DiGua 姓名板预留路径：

```text
DiGua 姓名板条件命中
-> ObserveAOEDiGuaBar(132334, 11.7, "准备吸奶盾", unit)
-> AOE事件类型 2 + AOE事件阶段 1（资源预留）
-> 若绑定技能身份明确的真实读条，进入上面的真实施法路径
-> 若没有可绑定的真实读条，保持预留并在超时后释放预警
-> 若实际多人吸收或当前群伤达到门槛，走反应式治疗入口
```

“读条后 2 秒”的基准是身份明确的施法记录 `cast.endsAt`；结束字段受保护时，使用可读 DurationObject 的结束时点或匹配成功终态的时刻。姓名板倒计时和时间接近的匿名技能不再单独生成阶段 3，也不能生成阶段 5 停手窗口。可信施法结束后的完整 2 秒仍保留；其间实际吸收采样不能覆盖已绑定读条的结束锚点。只有可信机制预铺允许全员健康时开美德。

类型 2/阶段 5 位于 `virtueReadyAt` 前最后一个 GCD 的预留区间，不是普通 AOE 的读条前窗口。App 运行时进入该阶段时必须清除已排队的普通 GCD，并独立于模块规则顺序拦截新普通 GCD；圣疗术、非 GCD、驱散和受伤友方 NPC 治疗可以通过。该保护避免阶段切换前已经排队的圣光术、神圣震击等技能把美德推迟一个 GCD。

`Fuyutsui/core/aoewarning.lua` 中只有图标 `132334` 或名称 `准备吸奶盾` 可进入这条 `diguabar` 路径。事件完成后阶段 3 保持到美德得到确认，以及治疗吸收生命周期或本地窗口结束；不得在首次零吸收采样时立即退回阶段 1。

没有可确认的真实读条时，只有至少 3 个有效单位各自达到至少 10% 最大生命值的吸收量、合计吸收比例至少达到 45%，并连续两帧满足条件时，才允许建立反应式吸收事件；最大生命值不可读时保持 fail-closed，不触发该事件。

## 与真实读条路径的关系

兼容桥仍监听 `UNIT_SPELLCAST_START/STOP/INTERRUPTED/FAILED/SUCCEEDED`，用于客户端能提供可用施法事件时的真实读条路径。历史日志显示，仅依赖这条路径可能失去执行时点：受保护字段或缺失终态会使事件长期停留在阶段 1。

因此吸奶盾允许两条输入进入同一个 AOE 状态机：

- 可用的真实施法事件按实际 `cast.endsAt + 2 秒` 提交吸奶盾事件。
- 技能身份明确且真实结束时点不可用时，匹配成功终态回调时刻作为实际回退；缺少技能身份或匹配终态时，姓名板信号保持资源预留，由实际多人治疗压力兜底。
- DiGua 预留事件按姓名板 `unitKey` 分离并分配独立内部事件 ID；只有同一单位的重复回调按影响时点去重，姓名板移除只取消该单位的事件，不能按全局图标或时间合并多个怪物。

可信读条终态和已确认的实际多人吸收可以生成 `类型 2 + 阶段 3`；姓名板预警自身只预留资源。模块消费协议阶段，不自行按怪物名字或裸倒计时推断成功。

## 不可破坏约束

- 不得再次通过兼容桥自己的 `addonTable.CustomEncounterBar` 尝试钩住 DiGua。
- 不得依赖退出游戏后才更新的插件日志驱动实时状态。
- 不得仅凭单个吸收数值、全员血量或战斗时间构造阶段 3；无 DiGua 的反应式吸收事件必须满足当前代码中的多单位比例阈值和连续两帧门槛。
- 可信真实读条结束后必须等待完整 2 秒；姓名板倒计时到点不能伪造成功。实际多人吸收形成的反应式事件不冒充读条完成。
- 不得删除或仅依赖模块规则实现类型 2/阶段 5 的最后 GCD 保护；进入阶段时必须作废既有普通 GCD 待发送动作。
- 美德链路修改不得顺带调整其他技能优先级；若正义盾击、牺牲祝福或消耗品等奶骑独立优先级发生变更，必须在优先级文档、模块 JSON 和契约测试中同步记录。
- 不得修改或打包分发第三方 DiGua 源码。
- 不得改变模块对 `AOE事件类型 == 2 && AOE事件阶段 == 3` 的消费契约，除非协议生产者、消费者、回放和迁移同时更新。
- 普通 AOE 继续要求匹配真实敌方读条；不得复用吸奶盾的裸姓名板倒计时提交方式。
- 预测时间、实际结束时间和美德可用时间必须保持独立：已绑定真实读条时，预测只允许影响资源预留；成功终态必须重新计算 `impactAt`、`virtueReadyAt` 并将锚点标记为 `actual`。没有可绑定真实读条时，DiGua 仅保留预警身份，不提供执行授权。
- 任何新数据源接入前必须先定义其证据等级和覆盖优先级。必须在 Lua 回放中覆盖“预测时间与成功时间不同”“受保护结束时间缺失”和“无终态仅预留、无关受保护读条不触发”三种场景。

当前 Lua `DebugLog` 是空实现，`/fu aoedebug` 只切换标志，不能据此取得逐次事件明细；普通 App 日志未传输的 `cast.endsAt`、GUID 和完整错误文本不能靠文档补成已观测事实。

## 日志验收标准

可信读条路径的验收需要以下证据；当前日志未提供的结束时点必须另行采集，不能推算成已观测值：

1. `AOE预警：治疗吸收 / 资源预留`。
2. 美德允许执行时点前进入类型 2/阶段 5；此后不得再出现普通 GCD 的实际投递，运行时拦截日志可以作为辅助证据。
3. 真实施法路径在 `cast.endsAt + 2 秒`、受保护终态路径在终态回调时刻 + 2 秒；无可匹配终态时不得仅靠 DiGua 倒计时出现 `AOE预警：治疗吸收 / 等待生效`；真实读条成功后必须切换为 `impactAnchor=actual`，姓名板预留保持 `impactAnchor=diguabar`，不能进入执行窗口。普通 Shigure 日志不声称传输未进入协议的 `cast.endsAt`。
4. 随后第一个符合条件的 GCD 为 `施放 美德道标`。
5. 最终出现 `技能确认：美德道标 已释放`；只有“已投递到 WoW 进程”不算成功。

实际多人吸收建立的反应式入口不要求先经过读条预留和阶段 5；它需要有效多人吸收、连续采样与最终美德确认的证据，不冒充可信读条路径。

2026-09-03 用户提供的早期实战日志已有两次“姓名板倒计时到美德确认”的闭环：

- `01:49:46` 进入资源预留，`01:50:01` 进入等待生效并投递美德，`01:50:03` 确认释放。
- `01:51:28` 进入资源预留，`01:51:46` 进入等待生效并在同秒确认美德释放。

这些记录只证明历史版本曾走通倒计时回退，当前已取消以裸倒计时授予执行资格。它们不能替代现役条件的实战验收。阶段时间会受扫描采样和姓名板首次满足条件的时刻影响，验收重点是所选时点锚点正确、完整 2 秒后置延迟、阶段 5 后无普通 GCD 抢占，以及最终动作确认，而不是日志秒数必须完全相同。

## 修改与验证清单

修改上述三处事实来源或相关同步/打包逻辑前，必须逐项确认：

1. 本文描述与生产代码仍一致。
2. `Tests/Shigure.Core.ContractTests/Fixtures/aoe-warning-replay.lua` 覆盖真实结束时点、受保护终态回退、预测覆盖保护，无终态仅预留，以及无关受保护读条拒绝匹配。
3. `Tests/Shigure.Core.ContractTests/Program.cs` 仍锁定姓名板事件、`132334`、`11.7`、取消入口、错误钩子禁令，以及阶段 5 的运行时统一 GCD 保护和待发送动作作废。
4. 运行 `luajit Tests/Shigure.Core.ContractTests/Fixtures/aoe-warning-replay.lua Fuyutsui/core/aoewarning.lua`。
5. 运行完整契约测试；若仓库已有无关失败，必须单独报告，不能把 Lua 回放通过等同于全套通过。
6. 新包实战至少验证一次“资源预留 -> 最后 GCD 保护 -> 结束后 2 秒进入等待生效 -> 美德已释放”，并保留真实读条结束时点、阶段切换、阶段 5 后动作和最终确认的时间戳日志。

若未来确认 DiGua 改变了副本、地图、单位筛选、图标或 11.7 秒参数，必须同时更新桥接、本文和契约测试；不能只改单个常量。
