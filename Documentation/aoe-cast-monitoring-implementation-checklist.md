## 已确认事实

- DiGua 是 AOE 机制名称和事件类型的权威来源；在受保护环境仍可能输出 `spellID=0`，`Fuyutsui/core/diguabridge.lua` 是当前兼容映射的唯一机器可读来源。兼容按关键能力检测，版本字符串只用于诊断。
- 2026-08-28 至 2026-08-31 的本机战斗日志确认：“鲜血献祭”的仪式首领真实读条是 `1306517`，随后施加到队员的治疗吸收光环是 `1306550`；原清单“使用同一个 Spell ID”的假设不成立。
- 2026-09-01 实战日志确认 DiGua 桥接能够重发 `1306517`，但大秘境战斗中的敌方 Spell ID、敌对状态和数值施法时间可能被客户端保护；受保护值不能在 Lua 中比较或参与时间运算。
- 2026-09-01 23:42 实战日志进一步确认，同一 `UNIT_SPELLCAST_START` 处理周期中可读敌方读条可能先于 DiGua 创建对应时间轴；Fuyutsui 必须短暂保存可读候选，不能假设预警一定先到。普通 `STOP` 也不能作为失败诊断，只有明确终态才能增加成功或失败计数。
- DiGua 的“准备吸奶盾”预警只负责提前预留资源，不能单独证明伤害或治疗吸收一定会发生。
- 普通 AOE 必须等待 DiGua 对应 Spell ID 的真实敌方读条；吸奶盾还可使用现役桥接复刻的姓名板倒计时入口。
- 怪物可能在读条过程中被暂时打断，随后重新读条；中断不能删除整个预警。
- 怪物可能在读条过程中死亡；死亡后不会产生对应 AOE 或治疗吸收，必须取消事件。
- 普通 AOE 需要在真实读条剩余 1 秒内预铺美德；吸奶盾优先在真实读条实际 `cast.endsAt + 2 秒`、结束时点不可用时在 DiGua 姓名板倒计时 `11.7 + 2 秒`后预铺美德。真实读条由 `UNIT_SPELLCAST_START` 主动建立，时间轴只负责语义预留和后续合并。
- 全员满血不是取消预铺美德的依据。只要对应读条已被确认并到达正确执行时点，满血预铺仍然有效。
- 战斗状态只能作为辅助信息，不能替代 DiGua Spell ID 与真实读条确认。

## 实施前置条件

- 当前实际安装的 DiGua 源码位于仓库外：`World of Warcraft/_retail_/Interface/AddOns/DiGuaTimelineAudioHelper`。
- DiGua 使用禁止演绎分发的许可，本仓库不得分发修改版；受管理桥接位于 Fuyutsui 内部，以关键时间轴 API 能力探测运行，`FuyutsuiDiGuaBridge` 仅保留兼容入口。检测到的版本只用于诊断，不作为硬编码门禁。
- 桥接实现随 Shigure 运行资源和 Fuyutsui 同步；DiGua 升级后由关键时间轴 API 能力探测决定是否启用，缺少关键 API 时安全降级。桥接不修改原始 DiGua，兼容目录不持有独立逻辑。
- 不允许只修改本机已安装的 DiGua 后直接打包 Shigure；该改动会被 DiGua 更新覆盖，也无法随 Shigure 交付给其他环境。
- 在编码前使用目标 WoW 客户端验证 `C_EncounterTimeline.GetEventState` 的真实返回类型、`Canceled`/`Finished` 枚举值、事件顺序及受保护值行为；验证失败时不得依赖该 API 推断成功。

## 当前问题

### DiGua 数据在时间轴边界丢失（已由 Fuyutsui 内置桥接层处理）

DiGua 调用 `CustomEncounterBar` 时已经知道机制语义和来源单位，但
`DiGuaTimelineAudioHelper/EncounterEventsCenterCountdown.lua` 当前把所有自定义时间轴事件的
`spellID` 固定写成 `0`。为遵守第三方许可，Shigure 不改写该文件；Fuyutsui 内置桥接保留原事件，
并只对规范预警重发带真实敌方读条 Spell ID 的事件。

### 旧 Fuyutsui 将吸奶盾倒计时当作完成信号

旧候选的 `Fuyutsui/core/aoewarning.lua` 允许治疗吸收事件在倒计时归零后直接从阶段 1 进入阶段 3，
没有要求出现相同 Spell ID 的真实读条。因此怪物死亡、读条未发生或预警过期时仍可能释放美德。

### 普通 AOE 与吸奶盾使用了不同的可信度标准

当前真实读条匹配仅接受普通 AOE（事件类型 1），吸奶盾（事件类型 2）无法进入同一套读条监测。
两类事件应共享统一的匹配、重读、成功、取消和超时状态机，仅保留执行时点差异。

### 中断和成功的生命周期处理不准确

- `UNIT_SPELLCAST_INTERRUPTED` 当前删除整个预警，导致怪物重新读条时无法再次匹配。
- `UNIT_SPELLCAST_STOP` 当前可能直接被当作成功完成，无法可靠区分成功、中断、失败和死亡。
- 敌方 `UNIT_SPELLCAST_SUCCEEDED` 当前没有进入 AOE 状态机。
- DiGua 主动取消时间轴与时间轴自然归零目前没有形成可靠的不同语义。

## 目标事件契约

### 权威来源

| 信息 | 权威来源 | 说明 |
| --- | --- | --- |
| 机制是否需要预警 | DiGua | Fuyutsui 不自行猜测副本机制 |
| 事件类型 | DiGua | 通过规范名称传输：`准备AOE=1`，`准备吸奶盾=2`；Fuyutsui 只在一个入口解码 |
| Spell ID | `Fuyutsui/core/diguabridge.lua` | 映射最初由 DiGua 调用点和战斗日志核实；桥接按关键 API/数据能力传递非零真实读条 Spell ID，版本字符串只用于诊断 |
| 真实读条开始与时长 | WoW 施法事件与 `UnitCastingInfo`/`UnitChannelInfo` | `UNIT_SPELLCAST_START` 直接建立读条实例；没有成功终态时只保留资源预留，不推断施法成功 |
| 读条成功、中断或失败 | WoW 施法事件 | 决定完成、等待重读或取消本次施法 |
| 施法者死亡 | WoW 单位/战斗事件 | 终止对应事件 |
| DiGua 主动取消 | DiGua 时间轴取消信号 | 终止对应事件 |
| 美德及后续技能选择 | 奶骑模块 | 只消费 Fuyutsui 输出的可信阶段 |

### 匹配条件

真实读条只有同时满足以下条件才属于当前预警：

1. 存在尚未取消或超时的 DiGua AOE 预警。
2. DiGua 预警携带非零 Spell ID。
3. 字段可读时，敌方真实读条的 Spell ID 与预警 Spell ID 相等，且读条来自可攻击单位。
4. 字段受保护时，仅接受姓名板单位且 DurationObject 可用、并与新建 DiGua 预警相差不超过 0.5 秒的同帧读条；不得把任意无目标读条或旧预警附近的读条作为匹配。

`castGUID` 和 `unitGUID` 只用于跟踪同一次实际施法的开始、结束、中断和死亡，不作为另一套机制配置来源。

### 时间轴传输契约

DiGua 自定义时间轴至少通过 `C_EncounterTimeline.AddScriptEvent` 传递以下信息：

| 字段 | 用途 |
| --- | --- |
| 运行时事件 ID | 区分每一条预警，并关联后续状态变化与移除 |
| `overrideName` | 使用规范名称传输事件类型 |
| `spellID` | 传输该机制的真实非零 Spell ID |
| `duration` | 仅用于资源预留和候选读条排序，不证明施法成功 |

Fuyutsui 必须监听 `ENCOUNTER_TIMELINE_EVENT_STATE_CHANGED` 并在事件被移除前缓存
`C_EncounterTimeline.GetEventState`。普通 AOE 的 `Canceled` 时立即取消；吸奶盾桥接重建期间的
`Canceled` 只保留阶段 1 资源预留，仍禁止进入美德窗口；状态为 `Finished` 或自然归零时按真实读条状态继续处理。
如果移除时没有可判定状态，必须按取消处理，不能保留可释放美德的执行窗口。

### 安全降级

- 普通 AOE 的 Spell ID 为 `0`、缺失、受保护且无法窄时间匹配时，只进入资源预留，不进入美德执行阶段；吸奶盾只有严格姓名板回退条件成立时例外。
- 敌方事件 Spell ID 受保护时，普通 AOE 仍使用窄时间相关性确认；吸奶盾额外复用 DiGua 的姓名板/副本/地图/等级/精英/无目标上下文，并可由该倒计时在后置 2 秒后提交阶段 3。真实读条入口仍需同一单位校验；条件失效、明确取消或失败不能进入阶段 3。
- 预警存在但始终没有匹配读条时，超时后结束且不释放美德；“静默”只指不施放技能，仍必须写诊断日志。
- 无 DiGua 预警时，即使观察到相同 Spell ID 的敌方读条，也不由预警链释放美德；真实群体缺口仍可触发现有反应式群疗。
- 不在 Fuyutsui 中复制 DiGua 的 AOE Spell ID 清单，避免两个事实来源漂移。

## 统一状态机

| 内部状态 | 协议输出 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| 无事件 | `类型 0 + 阶段 0` | 无有效预警 | 收到有效 DiGua 预警 |
| 资源预留 | `对应类型 + 阶段 1` | 收到可识别类型的 DiGua 预警，Spell ID 可以缺失 | 匹配读条、取消、死亡或超时 |
| 已匹配读条 | 根据事件类型和剩余时间输出 | 相同 Spell ID 的敌方读条开始 | 成功、中断、失败、死亡或取消 |
| 普通 AOE 最后安全 GCD | `类型 1 + 阶段 5` | 已匹配普通 AOE，进入最后一个安全 GCD | 进入最后 1 秒、中断或取消 |
| 普通 AOE 美德窗口 | `类型 1 + 阶段 2` | 已匹配普通 AOE，读条剩余不超过 1 秒 | 成功、中断、死亡或取消 |
| 普通 AOE 生效窗口 | `类型 1 + 阶段 4` | 普通 AOE 读条确认成功 | 本地生效窗口结束或事件取消 |
| 吸奶盾等待生效 | `类型 2 + 阶段 3` | 真实读条以记录的 `cast.endsAt + 2 秒`可信提交，或严格 DiGua 姓名板回退以 `11.7 + 2 秒`提交 | 实际吸收完成、等待窗口结束或事件取消 |

### 中断与重读

```text
资源预留
-> 匹配读条开始
-> INTERRUPTED / FAILED
-> 清除本次 castGUID
-> 返回资源预留
-> 等待相同 Spell ID 再次开始
```

中断只结束本次读条，不删除 DiGua 预警。重新读条必须重新记录开始时间、结束时间和新的 `castGUID`。

### 死亡与取消

```text
任意未完成状态
-> 施法者确认死亡，或 DiGua 明确取消事件
-> 清除预警及当前读条
-> 输出 类型 0 + 阶段 0
-> 不释放美德
```

名称板消失本身可能表示死亡、离开视野或超距，不能由 Fuyutsui 单独推断死亡；但 DiGua 若因此明确调用时间轴取消，Fuyutsui 应将该取消视为预警失效。

### 并发与归属

- 每条 DiGua 时间轴事件以运行时事件 ID 独立保存，每条事件同一时刻最多跟踪一个实际读条。
- 每个实际读条实例只能分配给一条预警，不能同时推进多条相同 Spell ID 的事件。
- 同一 Spell ID 存在多条候选预警时，只在尚未绑定读条的有效事件中选择预计发生时间与真实读条结束时间最接近的一条；距离相同则选择较早创建的事件。
- 中断、失败、死亡和取消只修改所属事件；处理后必须重新计算当前输出，不能直接把全局阶段清零。
- 多个事件同时可输出时，按 `阶段 2 > 阶段 3 > 阶段 5 > 阶段 4 > 阶段 1` 选择当前协议输出；同阶段选择预计发生时间更早的事件。
- 匹配前的施法者死亡由 DiGua 通过所属事件 ID 的取消负责；匹配后的死亡由 Fuyutsui 保存的 `unitGUID` 精确处理。
- 收到新的 `ADDED` 事件时，先清除相同运行时事件 ID 的旧状态缓存、旧施法实例和旧创建序号，再作为全新事件登记。

### 施法终态归并

- 每个 `castGUID` 只能提交一次终态。
- 同一个事件循环内收到多个终止信号时，优先级为 `死亡/DiGua 取消 > INTERRUPTED/FAILED > SUCCEEDED > STOP 未决`。
- `STOP` 只触发下一事件循环的归并，不自行提交成功。
- 终态一旦提交，随后到达的相同 `castGUID` 事件全部忽略，不能覆盖已经提交的结果。
- 因此同一循环中 `SUCCEEDED` 后又收到 `INTERRUPTED` 时按中断处理；成功已经提交后才迟到的 `INTERRUPTED` 则忽略。

### 吸奶盾等待结束

- 吸奶盾由真实读条的实际 `cast.endsAt + 2 秒`或 DiGua 姓名板倒计时 `11.7 + 2 秒`可信提交后进入阶段 3，并设置“尚未观察到实际吸收”。
- 只要任一有效队伍成员的治疗吸收首次大于 `0`，标记“已经观察到实际吸收”。
- 在尚未观察到实际吸收时，当前吸收为 `0` 不能结束阶段 3，只能等待最多 10 秒的本地窗口。
- 已经观察到实际吸收后，所有有效队伍成员的治疗吸收连续两个有效更新周期均为 `0` 时结束阶段 3。
- 在可信提交前，DiGua 取消、施法者死亡、读条中断、失败或倒计时条件失效都会取消本次事件并回到资源预留；提交后，阶段 3 仍由实际吸收或本地 10 秒窗口结束。

### 时间参数

- 普通 AOE 美德窗口继续使用 `virtueWindowSeconds=1`。
- GCD 输入余量继续使用 `inputMarginSeconds=0.35`，并结合实时公共冷却计算阶段 5。
- 普通 AOE 生效窗口和吸奶盾等待生效窗口继续使用 `impactActiveSeconds=10`。
- 没有匹配读条时，预警最多保留到预计发生时间后 10 秒。
- 读条被中断或失败时，等待重读窗口至少延长到当前时间后 10 秒；后续每次真实重读按新的结束时间重新计算。成功提交前，DiGua 取消或施法者死亡始终立即终止。

### 普通 AOE 的不可避免边界

普通 AOE 为了在伤害前预铺美德，必须在读条最后 1 秒作出决定。如果美德已经投递后读条才被打断或怪物才死亡，已发送技能无法撤回。验收标准是：所有发生在美德投递前的中断、失败、死亡和取消都必须阻止释放。
