## 设计目标

奶骑的治疗优化不是单纯追求面板治疗量，也不是单纯压低过量治疗，而是在有限的 GCD、施法时间、圣能和冷却资源内：

1. 优先避免目标在下一次高压中死亡。
2. 在美德 9 秒窗口内最大化有效治疗和美德转移治疗。
3. 保证圣能生成、消耗和神圣意志之间的循环。
4. 让美德覆盖多人高压主体，减少冷却真空期。
5. 在不牺牲安全血线的前提下，减少真正无意义的过量治疗。
6. 同时适用于 5 人小队和超过 5 人的团队。

## 关键机制

### 美德覆盖

美德为瞬发技能，占用 GCD，持续 9 秒。

5 人小队中，美德覆盖：

```text
主目标 + 其他 4 个成员
```

超过 5 人的团队中，美德覆盖：

```text
主目标 + 随机 4 个掉血单位
```

因此，多人团队不能假设所有受伤单位都获得美德；美德释放后必须读取实际 buff 目标。

美德的转移规则是：

```text
对其他已获得美德的目标进行治疗
=> 该治疗量的 15% 转移给美德主目标

直接治疗美德主目标
=> 不触发这部分 15% 转移
```

因此，美德不是单目标抬血技能。只有在主目标之外还有足够多的有效治疗需求时，美德才有较高价值。

### 治疗量基准

使用一次未暴击神圣震击的有效治疗量作为 `S`：

| 技能 | 无美德 | 美德期间 | 说明 |
| --- | ---: | ---: | --- |
| 神圣震击 | `1S` | `1.5S` | 产圣能 |
| 圣闪 | `1S` | `1.5S` | 读条、产圣能 |
| 圣光术 | `4S` | `6S` | 读条、产圣能 |
| 灌注圣闪 | `4S` | `6S` | 瞬发、产圣能 |
| 荣耀圣令 | `4S` | `6S` | GCD、消耗圣能 |
| 黎明之光 | `1S` | 约 `2S` | GCD、消耗圣能 |
| 圣洁鸣钟 | `3S` | `6S` | 30 秒 CD、产生 5 圣能和神圣意志 |
| 光环掌握 | `6S` | `12S` | 3 分钟 CD、产生 5 圣能、没有神圣意志 |

实战基准约为：

```text
S ≈ 全团总血量的 8%–10%
S ≈ 坦克血量的 6%–7%
```

因此圣光术、灌注圣闪和荣耀圣令都属于大治疗，不应被视为普通小额填充技能。

### 技能时间成本

- 美德、荣耀圣令、黎明之光等瞬发技能仍然占用 GCD。
- 圣光术和普通圣闪是读条技能。
- 灌注圣闪和神性圣光术是瞬发高治疗量产能技能。
- 裸读圣光术的读条速度只比 GCD 多约 `0.2 秒`。
- 审判虽然产圣能，但没有治疗效果且占用 GCD。

在美德 9 秒窗口内，实际可用动作数量有限。每次审判、普通驱散或低收益动作都会消耗一个有限的治疗机会。

## 压力分类

团队高压必须区分为两类。两类都可能使用美德，但使用方式不同。

### 多人同时大量掉血：全团爆发高压

特征：

```text
短时间内多个目标同时出现大缺口
BurstGroupNeed 很高
```

目标是尽快把多个目标拉回安全血线。此时允许一定安全性过量，不应因为某个目标当前缺口尚未达到单次技能的完整治疗量，就强制降级到低治疗技能。

### 多人持续少量掉血：全团持续高压

特征：

```text
单次伤害不大
但多个目标持续出现缺口
未来 9 秒累计治疗需求高
SustainGroupNeed 很高
```

目标是让美德覆盖持续压力主体，并用产能技能和荣耀圣令建立稳定圣能循环。此时不应因为当前血量暂时回升就立即退出高压策略。

### 单目标紧急治疗

单个目标的大缺口不是本文定义的团队高压，但它拥有最高的生存优先级：

```text
紧急单目标治疗 > 美德转移收益 > 过量控制
```

如果直接治疗主目标才能避免死亡，必须直接治疗，不得为了等待美德转移而延迟。

## 压力指标

运行时应同时维护以下指标，不再只依赖当前 `DTotal` 或固定血量阈值。

```text
SingleNeed
    单个目标当前及短期未来的预计缺口

BurstGroupNeed
    未来 1–2 个 GCD 内，多人同时出现的预计缺口

SustainGroupNeed
    未来 9 秒内，多人累计出现的预计缺口

SpreadCount
    未来 9 秒内预计需要治疗的目标数量

ExpectedNeed(unit)
    当前缺口 + 预测伤害 + 安全血线余量
```

### 预期需求

对目标的治疗需求不能只看当前血量：

```text
ExpectedNeed(unit) =
    当前缺口
    + 下一次高压前的预测伤害
    + 保持安全血线所需的余量
```

预测范围至少应包括：

- 下一个高压事件。
- 接下来 1–2 个 GCD 内的伤害。
- 当前美德 9 秒窗口内的预计伤害。
- 坦克已经确定会承受的伤害。

### 两类过量

```text
安全性过量：
    为了让目标扛过即将到来的高压而提前增加的血量。
    可以接受。

无效过量：
    当前和短期未来都没有明显压力，治疗直接溢出。
    应该避免。
```

## 预警来源与可信度

“预测伤害”必须区分为事件时间预测和伤害数值预测。DiGua 不仅提供吸奶盾预警，也提供普通 AOE 预警；两者都应参与美德、圣能和鸣钟的时间调度，但可信边界不同。

| 来源 | 可以可靠推断 | 不能单独推断 | 用途 |
| --- | --- | --- | --- |
| 普通 AOE 预警 + 匹配的真实敌方读条 | AOE 大致发生时间、最后安全 GCD | 实际伤害量、最终命中人数 | 提前预留资源，并让美德覆盖 AOE 主体 |
| 吸奶盾预警 + 匹配的真实敌方读条 | 吸收阶段的大致发生时间 | 吸收量和实际覆盖目标 | 提前预留资源，并按吸收专用时点进入阶段 3 |
| 任一类型的严格 DiGua 姓名板回退 | 真实结束字段不可用时的替代时点 | 读条一定成功、伤害一定发生 | 只有满足同一套来源单位、地图、单位状态和时间相关性条件时才可使用 |
| 仅有 DiGua 时间轴、没有匹配读条 | 机制可能即将发生 | 读条成功、伤害一定发生 | 资源预留，不直接释放普通 AOE 美德 |
| 团队血量连续变化 | 近期压力趋势 | 下一次伤害的精确数值和时间 | 高压预警、延迟退出高压状态 |

### 普通 AOE 预警

普通 AOE 也必须进入压力调度链路：

```text
DiGua 普通 AOE 预警
-> 资源预留
-> 匹配同一非零 Spell ID 的真实敌方读条
-> 读取真实读条结束时间和剩余时间
-> 最后安全 GCD / 普通 AOE 美德窗口
-> 美德覆盖 AOE 主体
-> 按实际血量和当前场景执行鸣钟、光环掌握、荣耀圣令等后续治疗
```

只有时间轴预警而没有匹配读条时，普通 AOE 只能预留资源，不能单独构造美德执行窗口。普通 AOE 和吸奶盾必须采用相同的可信度判断：预警本身不是施法成功证据，必须存在匹配的真实读条，或满足统一的严格 DiGua 姓名板回退条件；读条被打断、失败、施法者死亡、事件取消或超时，都不能进入执行窗口。

如果团队已经出现真实多人缺口，仍然可以由当前血量场景触发反应式群疗；这属于事实驱动的治疗，不是把预警当作伤害事实。

### 吸奶盾预警

吸奶盾使用更严格的时序：

```text
真实读条 cast.endsAt + 2 秒
或严格 DiGua 姓名板回退 11.7 + 2 秒
-> 阶段 3
-> 美德
-> 等待实际治疗吸收
```

进入阶段 3 只证明预计进入吸收处理窗口，不证明吸收量已经出现。必须继续读取真实治疗吸收，不能用预警时间代替实际治疗需求。

但它与普通 AOE 使用同一套事件可信度判断。区别只有执行时点：普通 AOE 必须在确认真实读条后、读条剩余 1 秒内释放美德；吸奶盾在真实读条结束后还必须等待 2 秒，或在严格姓名板回退结束后等待 2 秒，再进入阶段 3。

### 统一事件判断

两类事件均应遵循：

```text
DiGua 预警
-> 资源预留
-> 匹配真实读条或严格回退锚点
-> 检查读条是否成功完成
-> 检查事件是否被取消、打断、失败或施法者死亡
-> 计算对应的美德执行时点
-> 进入普通 AOE 窗口或吸奶盾阶段 3
```

禁止形成以下不一致：

```text
普通 AOE：因为匹配不到读条而直接按时间轴释放
吸奶盾：要求真实读条或严格回退
```

正确的差异应当是：

```text
可信度判断：普通 AOE 与吸奶盾一致
生效时间计算：普通 AOE 为读条剩余 1 秒窗口；吸奶盾为读条结束后 2 秒
```

### 预警如何参与压力判断

预警只负责回答：

```text
高压可能何时开始？
```

当前血量、治疗吸收和连续趋势负责回答：

```text
现在是否已经需要治疗？
```

最终决策应合并两者：

```text
已确认的普通 AOE 或吸奶盾时点
+ 当前多人缺口
+ 团队血量趋势
+ 9 秒美德窗口内的可用 GCD 和资源
```

不能仅因为 DiGua 报警就释放美德，也不能因为当前血量尚未下降就完全忽略已经确认的普通 AOE 读条。

## 美德触发设计

### 美德价值

美德预期价值应计算为：

```text
VirtueValue =
未来 9 秒内对非主目标的有效治疗
所产生的 15% 转移治疗总量
```

对于多人团队，释放前使用预计覆盖概率；释放后使用实际 buff 目标。

```text
ExpectedVirtueValue =
Σ(
    目标被美德覆盖的概率
    × 该目标未来 9 秒的有效治疗量
    × 15%
)
```

### 默认不使用美德的情况

```text
只有 1 个目标掉血
只有 2 个目标轻伤
美德主目标是唯一需要治疗的目标
未来几秒没有多人高压
预计非主目标治疗量不足以产生有意义的转移
```

### 触发条件

美德进入候选需要满足以下任一类条件：

```text
多人爆发高压即将开始
且美德可以覆盖高压主体
```

或：

```text
多人持续高压已经开始
且 SpreadCount 达标
且未来 9 秒预计转移收益足够
```

初始调参可以使用以下参考值，最终必须通过实战日志调整：

- 5 人小队：至少 2–3 个非主目标有持续预期缺口，或预计转移收益达到约 `2S`。
- 多人团队：至少 4 个目标有预期缺口，或已经确认进入多人团体高压。

这些是候选门槛，不是永久写死的规则。

## 5 人小队设计

5 人小队中，所有成员都能获得美德，覆盖是确定的。

```text
VirtueValue_5 =
未来 9 秒内其他 4 个目标的有效治疗总量 × 15%
```

适合使用美德的场景：

- 多人同时出现大缺口。
- 多人持续出现小到中等缺口。
- 未来 1–2 个 GCD 内确定会进入团体高压。

不适合使用美德的场景：

- 只有一个目标掉血。
- 只有一个非主目标需要治疗。
- 主目标本身是唯一重伤目标。

美德主目标可以优先选择未来需要转移治疗、但不一定会被持续直接治疗的关键目标。坦克通常是合理候选，但不能仅因为目标是坦克就固定选择。

## 多人团队设计

超过 5 人的团队中，美德覆盖具有随机性：

```text
主目标固定获得 buff
其他 buff 目标从掉血单位中随机选择 4 个
```

释放前不能假设所有受伤目标都能触发转移。释放后必须记录实际覆盖集合：

```text
VirtueBuffedTargets =
主目标 + 实际获得美德 buff 的其他目标
```

之后的治疗评分必须使用真实集合：

```text
治疗非主目标且该目标实际有 buff：
    直接治疗 + 15% 转移

治疗没有 buff 的目标：
    只有直接治疗
```

多人团队中的美德门槛应高于 5 人小队，除非已经确认进入大型团体高压。随机覆盖目标越多，越应使用实际 buff 结果重新规划，而不是沿用释放前的预计值。

## 9 秒美德窗口

美德是有限动作预算，而不是单纯的增益开关。

```text
可用动作数 =
floor((9 秒 - 延迟和确认余量) / 实际 GCD)
```

每个 GCD 重新评估：

- 当前目标预期需求。
- 技能有效治疗量。
- 美德转移治疗量。
- 圣能变化。
- 神圣意志价值。
- 过量治疗。
- 读条是否能在美德结束前生效。

读条技能必须检查落地时间：

```text
技能实际生效时间
<= 美德结束时间 - 安全余量
```

美德快结束时，不应开始一个无法在窗口内完成的圣光术读条。

## 技能决策

### 全团爆发高压

如果多人同时出现大量缺口：

```text
美德
→ 光环掌握（仅重大事件）
→ 荣耀圣令
→ 圣洁鸣钟
→ 荣耀圣令
→ 瞬发高治疗量产能技能
```

如果不使用光环掌握：

```text
美德
→ 圣洁鸣钟
→ 荣耀圣令
→ 灌注圣闪 / 神性圣光术
→ 荣耀圣令
```

### 全团持续高压

```text
美德
→ 圣洁鸣钟
→ 荣耀圣令
→ 灌注圣闪 / 神性圣光术
→ 荣耀圣令
→ 可有效读满的圣光术
```

持续高压时，裸读圣光术只比 GCD 多约 `0.2 秒`，且可提供约 `4S`、美德期间约 `6S` 的治疗，同时产生圣能，因此通常明显优于审判。

### 光环掌握

光环掌握是 3 分钟大爆发技能，不能作为常规群加手段。

只有在以下条件成立时才进入候选：

```text
光环掌握可用
且属于大型多人伤害事件
且团血有效缺口足以吸收大部分 12S
且使用后产生的 5 点圣能有机会消耗
```

如果光环掌握只能有效治疗少量缺口，应保留给后续大事件。

### 圣洁鸣钟

鸣钟是常规美德爆发窗口的主要群体技能：

```text
美德期间 6S 治疗
+ 5 点圣能
+ 神圣意志
```

判断条件：

```text
美德有效或即将有效
且多人有预期缺口
且未来存在足够圣能消耗机会
且不会严重浪费 5 点圣能
```

### 荣耀圣令与黎明之光

每次消耗圣能前比较：

```text
荣耀圣令预期有效治疗
vs
黎明之光对所有目标的总有效治疗
```

默认荣耀圣令优先，因为美德期间约为 `6S`，而黎明之光约为 `2S`。

黎明之光只在以下情况下使用：

```text
多个目标都有小缺口
荣耀圣令会严重过量
黎明之光总有效治疗高于荣耀圣令
没有更紧急的单目标救治
```

### 产圣能技能

站定且目标能够有效承受治疗时，优先级为：

```text
灌注圣闪 / 神性圣光术
> 可有效读满的圣光术
> 神圣震击
> 圣闪
> 审判
```

审判只有在以下情况下作为备用：

- 移动中。
- 其他治疗技能不可用。
- 没有目标能有效吃下圣光术。
- 读条无法在美德结束前完成。
- 必须立即产能且无法承担读条时间。

队伍满血时，灌注剩余不超过 `5 秒` 且圣能未满，应优先用灌注圣光闪现转化圣能；此窗口不能被审判或通用正义盾击抢占。灌注剩余超过 `5 秒` 时，审判才可作为健康场景的产能填充。

## 圣能和冷却管理

鸣钟和光环掌握都产生 5 点圣能，但只有鸣钟提供神圣意志。

必须增加圣能溢出检查，不应在满圣能时无条件连续释放两个产能冷却：

```text
光环掌握 → 鸣钟
```

必要时使用中间的荣耀圣令消耗圣能：

```text
光环掌握
→ 荣耀圣令
→ 鸣钟
→ 荣耀圣令
```

但如果当前存在立即减员风险，生存优先级高于圣能溢出控制。

## 美德调度状态机

建议使用以下状态：

```text
低压
高压预警
高压处理中
高压尾段
低压确认
```

### 低压

只有少量目标掉血，且近期没有多人高压：

```text
保留美德
直接治疗
恢复圣能
```

### 高压预警

预计 1–2 个 GCD 内进入多人高压：

```text
准备圣能和瞬发技能
不要提前浪费美德
```

### 高压处理中

多人高压已经开始：

```text
最多延迟一个 GCD 释放美德
```

### 高压尾段

美德结束后，不应因为一次采样暂时回血就立刻恢复低压优先级。继续处理预期需求，避免下一波压力到来前血线再次过低。

### 低压确认

只有连续多个 GCD 没有明显伤害，且没有新的 AOE 预警，才进入低压资源模式。

## 建议的评分模型

每个候选动作应至少评估：

```text
Score =
    生存收益
    + 有效治疗量
    + 圣能后续价值
    + 神圣意志价值
    + 美德转移收益
    - 无效过量
    - GCD 和读条成本
    - 冷却机会成本
```

其中生存收益的权重最高。任何可能导致目标在下一次高压中死亡的动作，即使理论过量较高，也不应被低治疗技能替代。

## 基础链路状态

本设计依赖以下基础链路；状态按当前源码、契约测试和 WoW 实战分别记录：

1. `pending`：线上实际加载模块与仓库版本一致性仍需重新打包并在 WoW 实战确认。
2. `changed-and-verified`：美德动作确认已收紧为匹配动作事件或无事件时的对应资源/冷却变化；源码和契约测试通过，WoW 实战仍 pending。
3. `changed-and-verified`：吸奶盾事件锚点和阶段 3 的本地状态机已有真实结束时间与严格回退路径；WoW 实战仍 pending。
4. `changed-and-verified`：阶段 5 普通 GCD 保护在 Runtime 层统一拦截，并保留圣疗术、非 GCD、驱散和受伤友方 NPC 治疗例外；WoW 实战仍 pending。
5. `pending`：运行时读取实际美德 buff 目标的多人随机覆盖结果仍需 WoW 客户端日志确认。

在第 1、5 项和 WoW 实战确认完成前，后续压力预测与优先级调优日志仍可能被错误的美德状态污染。

## 完成判定

本设计只有在以下条件都满足后，才可认为实现完成：

- 5 人小队和多人团队分别通过覆盖和目标选择回归。
- 多人爆发高压和多人持续高压分别通过回归。
- 美德不再因少量掉血被无意义消耗。
- 美德能够覆盖高压主体，且真空时间可从日志确认下降。
- 审判不会在有可有效治疗的圣光术时抢占 GCD。
- 光环掌握只在大型事件使用，不进入常规群疗循环。
- 美德、鸣钟和圣能消耗之间没有明显溢出或错过窗口。
- 实际有效治疗、转移治疗、过量治疗和生存结果均有日志证据。
- 完成定向契约测试、全量契约测试和目标 WoW 客户端实战验收。
